# WAVE 01 — macOS bundle inventory and size baseline

## Goal

Explain the 1.30 GiB arm64 / 1.57 GiB x86_64 DMG size with measured file-level
evidence before changing the PyInstaller spec. Produce a reproducible baseline
for both supported macOS architectures.

## In scope

- `build/macos/hpc-client-gui.spec`
- `scripts/release_macos.py`
- `scripts/report_bundle_sizes.py`
- `.github/workflows/release.yml` only if a reporting gap prevents diagnosis
- macOS CI artifacts and logs for the current release run

## Forbidden

- Do not remove QtWebEngine, `QtWebEngineProcess`, ICU, software-renderer
  libraries, or terminal assets based on size alone.
- Do not increase `HPC_GUI_DMG_BUDGET_MIB`.
- Do not disable the DMG budget check.
- Do not alter application behavior, updater asset names, signing mode, or
  release permissions.
- Do not publish, merge, push, or delete a release/tag from this wave.

## Procedure

1. Run the existing macOS packaging plan on arm64 and x86_64 CI runners using
   the exact locked release dependencies.
2. Preserve the generated `.app` directory before DMG creation.
3. Run:

   ```bash
   python scripts/report_bundle_sizes.py \
     --bundle "dist/HPC Client GUI.app" \
     --output "dist/bundle-size-report-macos-${MACOS_TARGET_ARCH}.txt"
   ```

4. Report, separately for each architecture:
   - total uncompressed bundle size;
   - compressed DMG size;
   - top 30 files;
   - top 20 grouped directories/frameworks;
   - QtWebEngine resources, Chromium helper/processes, ICU data, Qt plugins,
     Python runtime, app assets, documentation, licenses, and symbols;
   - duplicate files or duplicate architecture slices;
   - files not required by an exercised user path.
5. Compare the report with the smoke-test requirements in
   `scripts/macos_release_smoke.py` and the runtime imports in
   `src/hpc_gui/ui/widgets/terminal_widget.py`.

## Required evidence

- Two complete reports, one for `arm64` and one for `x86_64`.
- A table mapping every proposed removal to an observed runtime dependency
  and a replacement test.
- A size budget calculation showing the expected post-change DMG size.
- A statement that the terminal WebEngine path still works, or a separately
  approved product decision to replace that path.

## Acceptance criteria

- The largest contributors are named with exact paths and byte counts.
- No pruning change is proposed without a runtime or packaging test.
- The baseline can be regenerated by a new developer from the documented
  command and CI run URL.
