# GUI Visual Parity Report — Qt reference vs wx workspace

Generated against the integrated wx shell at branch `delegate7-layout`.
Qt remains the production runtime; this report measures how close the optional
wx workspace has come to it.

Screenshot sets compared:

- Qt reference: `audit/gui-screenshots/qt/` (7 files, pre-existing)
- wx candidate: `audit/gui-screenshots/wx/` (8 files, regenerated by
  `scripts/capture_gui_audit.py`, hashes in `HASHES.json`)

Both captured at 1100x720, language `en`.

## Verdict

```
GUI-WORKSPACE-001: COVERED
GUI-VISUAL-001:    PARTIAL
```

Structure matches: seven tabs in Qt's order, zero launcher-only pages, zero
unexpected detached frames, and 400 resize operations with every layout
invariant at zero. Content parity is partial — four surfaces still lack Qt
controls, listed below.

**Accepted duplicate:** `main.png` and `connection.png` are byte-identical
because the wx shell opens on the Connection tab, so its initial view *is* the
Connection surface. Qt's own `main.png` shows the same Login tab; its two files
differ only because they were captured at different moments with live terminal
content. Fabricating a difference in the wx set would misrepresent the
application, so the duplicate is recorded rather than engineered away.

| Qt control | wx |

as a separate primary tab (the accepted deviation carried from GUI-TERM-002),

## Known i18n gaps found during this work

- `transfer.conflict_message` is used by `create_transfer_conflict_dialog` but
  exists in neither `en.json` nor `tr.json`, so the conflict dialog renders the
  raw key. Pre-existing; not introduced by this migration group.
- Qt hardcodes its seven transfer column headers in English. The wx panel uses
  new `transfer.col_*` keys in both languages instead.
