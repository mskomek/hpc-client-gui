# HPC Client GUI feature guide

This guide records the current Qt production surfaces and the wx migration
surfaces using disposable mock data. The screenshots are generated by
`scripts/capture_wiki_screenshots.py` (Qt) and
`scripts/capture_wx_gui_guide.py` (wx). They are demonstrations, not proof of
connection to a real cluster.

## Runtime choice

The production default remains Qt (`DEFAULT_GUI_RUNTIME = "qt"`). The wx
surface is opened explicitly with `python -m hpc_gui --wx` and is the
migration candidate. Existing Qt screenshots are the “old GUI” reference;
the `wx-*.png` screenshots are the new GUI reference.

## Connection and security

The mock guide uses `127.0.0.1`-style fabricated data only. Real connection
usage still requires SSH host-key validation, authentication, and the existing
secret-store policy. Passwords, MFA responses, private keys, tokens, and real
cluster identifiers are never placed in screenshots.

## Files and SFTP

Local Files shows the local workspace. Remote Files uses the SFTP/file adapter
boundary and displays a fabricated `/scratch/demo` listing. Real upload,
download, rename, delete, conflict handling, and permissions remain backend
operations and must be tested against the applicable adapter or authorized
cluster; a screenshot alone is not evidence.

## Jobs and Slurm

The mock Jobs screen contains fabricated `RUNNING` and `PENDING` jobs. The
detached output example keeps stdout and stderr separate. Real `squeue`,
`scontrol`, `sbatch`, `scancel`, output backoff, and completion notifications
use the existing SSH/Slurm services. The local wire-level mock is covered by
`tests/support/mock_ssh_server.py` and `tests/test_mock_cluster_roundtrip.py`.

## Editor

The editor supports the migration’s existing async Save/Submit/Run pipeline.
For local scripts the semantic flow is save → upload → submit/run. For remote
scripts it is save → submit/run. The wx editor is not the Qt default runtime.

## Help, terminal, plugins and tools

The Help screenshot uses the shared catalog and active shortcut data. Terminal,
plugins, ANSYS Trusted Tools, updater and diagnostics keep their existing
security and lifecycle boundaries. Where the table says “no wx window adapter
yet”, that is an explicit remaining migration item, not a successful feature
claim.

## Recreate the evidence

```powershell
python scripts/capture_wiki_screenshots.py
python scripts/capture_wx_gui_guide.py
python -m pytest -q tests/test_mock_cluster_roundtrip.py tests/test_wx_editor_cross_view_actions.py
```

The first command refreshes old Qt reference images; the second captures the
new wx surfaces from the current source tree. Both use disposable fabricated
data and do not touch `.tmp/`.
